# Milestone 7: FastAPI GUI layer

## Objective

Create a separate GUI presentation layer for browser-based report viewing and analysis. This layer should reuse the same query services as the CLI and should not own data persistence or parsing logic.

## Scope

- Build a FastAPI application for reporting and analysis.
- Expose endpoints for run-based and aggregate views.
- Provide a browser-based interface for interactive exploration.
- Ensure the GUI shares the same service layer as the CLI.

## Design constraints

- Use FastAPI, not Django.
- Keep the GUI presentation-only.
- Do not allow the GUI to perform direct database writes or parsing.
- All data access should be mediated through the library services.

## Acceptance criteria

- The GUI can display a selected run summary.
- The GUI can display aggregate analysis over many runs.
- The API uses the same query layer as the CLI.
- The GUI can be started independently from the ingestion or CLI workflow.

## Example pytest cases

```python
# tests/test_gui_api.py
from fastapi.testclient import TestClient


def test_run_detail_endpoint_returns_200(client):
    response = client.get("/runs/abc123")

    assert response.status_code == 200
    assert "run_id" in response.json()


def test_summary_endpoint_returns_aggregate_data(client):
    response = client.get("/reports/summary")

    assert response.status_code == 200
    assert "totals" in response.json()
```

## Definition of done

This milestone is complete when the HTML or JSON views generated by the GUI are backed by the same library queries used by the CLI and the underlying data model.
